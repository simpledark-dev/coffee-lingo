TECH STACK (already decided — do not evaluate alternatives)

IMPORTANT DEVELOPMENT PHILOSOPHY

- We are building an MVP, not a full product
- If a feature is not necessary to validate the core loop, cut or defer it
- Prefer deterministic logic over AI-dependent runtime systems
- Prefer hardcoded/simple implementations for prototype-only parts when appropriate
- Prefer data-driven design for content systems that will expand later
- Identify what should be built now vs later
- If something is ambiguous, choose the simplest option that best supports the game vision

⸻

DEFINITION OF "PLAYABLE"

The prototype is playable when:
- A player can start a day, serve at least 5 customers using the constructive word bank, see evaluation scores (PERFECT/GOOD/UNDERSTOOD/MISSED), and reach a day-end summary screen.
- The core loop — customer speaks → player responds via word bank → idea-tag evaluation → customer reacts → next customer — functions end to end.
- It does NOT need to be pretty, polished, or content-complete.

⸻

CONTEXT

The game is a top-down pixel-style cafe language-learning game.
The player stays behind the counter.
Customers arrive and speak in the target language.
The player responds using a constructive word bank.
Evaluation is based on idea-tag matching, not grammar parsing.
The core philosophy is:
IDEA → EXPRESSION → REPETITION
