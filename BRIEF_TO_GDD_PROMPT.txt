You are a team composed of:

• a mobile game designer
• a systems designer
• a linguist specializing in second language acquisition
• a product designer

Using the Product Brief attached at the end of this prompt, generate a complete Game Design Document (GDD).

The goal is to produce a document detailed enough that a development team could implement the game without inventing mechanics.

Do not summarize the brief. Expand it into a concrete design specification.

⸻

IMPORTANT RULES

• The core learning philosophy and vision in the brief must remain unchanged.
• When multiple design options exist, choose one and justify it.
• Avoid high-level descriptions. Provide specific mechanics and interaction flows.
• Prefer clear rules, algorithms, and system behaviors over descriptive text.
• Assume the system must scale to thousands of dialogue variations without requiring manual scripting of each interaction.
• Favor data-driven and template-based systems over hardcoded dialogue.
• Assume the MVP focuses on the coffee shop scene only.

⸻

KEY DESIGN DECISIONS TO MAKE

The brief leaves several critical questions open. The GDD must resolve them.

1. Input Method
This is the most important design decision — it shapes the entire interaction system and evaluation logic.
Evaluate these options: word-bank selection, free typing, hybrid (word-bank with optional typing), or another approach.
Choose one for the MVP and justify it. Explain how it supports the learning philosophy (retrieval over recognition, idea-level correctness, communication before grammar).

2. Response Evaluation
Tightly coupled to the input method. Define exactly how the game determines whether a response is "correct enough."
Must support: imperfect grammar, mixed native/target language, and idea-level correctness (not literal translation matching).

⸻

THE GDD MUST INCLUDE

1. Game Overview
	• game concept
	• player experience goals

2. Core Gameplay Loop
	• detailed interaction flow
	• timing expectations (10–20 seconds per interaction)
	• how Idea Pressure works mechanically (time limits, queue pressure, customer patience)

3. Player Interaction System
	• how the player responds to customers
	• UI flow for interactions
	• input method decision and justification (see Key Design Decisions above)

4. Response Evaluation System
	• how the game determines whether a response is correct enough
	• how imperfect sentences are accepted
	• how idea-level correctness is detected
	• how native language mixing is handled

5. Dialogue System Architecture
	• dialogue templates
	• idea categories
	• how conversations are generated
	• how surface-level variation is created while repeating the same idea requirements

6. Scenario Generation System
	• how customers generate situations
	• how repetition is controlled without boredom (same idea, varied presentation)
	• how the system selects which ideas/words to target in a given session

7. Vocabulary System
	• idea cards
	• vocabulary acquisition flow (game-recommended words AND player-selected words)
	• word mastery levels
	• active word forcing mechanic — how the game challenges the player to use a target word in a conversation that doesn't obviously call for it
	• vocabulary compounding — how the system detects and rewards combining multiple learned words in a single response
	• vocabulary progression stages (survival → daily → workplace → social)

8. Customer AI System
	• customer types and personality behaviors
	• reaction logic (visual and mechanical)
	• regular customer relationship system

9. Progression System
	• skill progression
	• reward loop
	• meta progression (cafe upgrades, unlocks)

10. Cafe Upgrade System
	• upgrade mechanics
	• visual changes
	• gameplay effects (new scenarios, vocabulary, customer types unlocked)

11. Day / Session System
	• how days begin and end
	• summary screen content
	• micro achievements

12. UI and HUD Design
	• what information is shown to the player during gameplay
	• interaction UI elements
	• feedback indicators (customer reactions, word mastery, tips)

13. Audio Design
	• sound effects (door bell, coffee machine, customer reactions)
	• ambient audio
	• music direction

14. MVP Content Scope
	• vocabulary list (~30-50 expressions, organized by idea category)
	• number of dialogue templates
	• number of customers per day
	• scalability constraint: system must be architected to support thousands of words

15. Content Data Model
	• how vocabulary, idea cards, dialogue templates, and scenarios are structured conceptually
	• relationships between data entities (ideas → expressions → dialogue templates → scenarios)
	• how new content (words, templates, scenes) can be added without code changes

16. Example Gameplay Walkthrough
	• step-by-step example of a full day session (from day start to summary screen)
	• include at least 5 varied customer interactions showing different idea types
	• show how word mastery progresses across interactions

17. What This GDD Does NOT Cover
	• explicitly list post-MVP features that are out of scope (multiple districts, voice input, passive listening, etc.)
	• note any design decisions that should be revisited after MVP testing

⸻

OUTPUT FORMAT

Write the document as a clear, structured Game Design Document with sections and subsections.

The document should be practical for developers and product designers.
