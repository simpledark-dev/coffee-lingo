YOUR TASK

Implement Milestone 0 (bare loop) + Milestone 1 (basic systems) from DEV_PLAN.md.

This means building a fully playable prototype where a player can:
1. Start a day ("Day N" screen → tap "Open Shop")
2. Serve 8 customers by tapping words from a word bank and pressing Send
3. See evaluation scores (PERFECT/GOOD/UNDERSTOOD/MISSED) after each response
4. See tip rewards and a patience timer counting down
5. Use hints (idea hint, then English translation) with tip penalty
6. Reach a day-end summary (customers served, coins, reputation, words practiced, level-ups)
7. Start the next day with state persisted in localStorage (mastery, coins, reputation, day number)

// types.ts

interface Expression {
  id: string           // "parce_que"
  text: string         // "parce que"
  nativeText: string   // "because"
  ideaTags: string[]   // ["reason"]
  stage: number        // 1-4
}

interface DialogueTemplate {
  id: string
  ideaCategory: string
  difficulty: number
  customerLines: {
    text: string                          // "Je voudrais {quantity} {item}"
    variables: Record<string, string[]>   // { quantity: ["un", "deux"], item: ["café", "thé"] }
  }[]
  requiredIdeas: string[]    // ["confirmation", "{quantity}", "{item}"]
  bonusIdeas: string[]       // ["politeness"]
  followUpIds: string[]      // ignored for now
}

interface ResolvedExchange {
  customerLine: string       // "Deux cafés s'il vous plaît"
  requiredIdeas: string[]    // ["confirmation", "quantity", "item"] — {variables} resolved to tags
  bonusIdeas: string[]       // ["politeness"]
  wordBank: Expression[]     // 8 tiles
  templateId: string
  hintIdea: string           // "Confirm the order" — human-readable idea hint for hint level 1
  hintTranslation: string    // "Two coffees please" — English translation for hint level 2
}

type Score = 'PERFECT' | 'GOOD' | 'UNDERSTOOD' | 'MISSED'

interface EvaluationResult {
  score: Score
  coveredRequired: string[]
  coveredBonus: string[]
  tipAmount: number
}

interface PlayerState {
  currentDay: number
  coins: number
  reputation: number
  vocabulary: Record<string, VocabularyEntry>
  recencyBuffer: string[]
}

interface VocabularyEntry {
  masteryLevel: number       // 0-3
  totalSuccessfulUses: number
  sessionsUsedIn: number
  lastUsedDay: number
}

// Day summary data collected during gameplay
interface DaySummary {
  customersServed: number
  totalCustomers: number
  scores: Record<Score, number>  // count of each score type
  coinsEarned: number
  reputationChange: number
  wordsPracticed: number
  wordsLeveledUp: string[]       // expression IDs that leveled up
}

GAME LOGIC — lib/game.ts

Implement these pure functions:

1. **resolveTemplate(template, expressions) → ResolvedExchange**
   - Pick a random customerLine variant from the template
   - For each variable in the chosen line, pick a random value from its options
   - Fill the variables into the customer line text
   - Resolve requiredIdeas: for each entry, if it's a `{variable}` reference, look up the chosen variable value in expressions, get its ideaTags, and use those tags. If it's a plain string (like "confirmation"), keep it as-is.
   - Generate hintIdea from the template's ideaCategory (e.g., "ordering" → "Confirm the order")
   - Generate hintTranslation by replacing variables with their nativeText equivalents
   - Generate word bank (call generateWordBank)

   CRITICAL: The `{variable}` → idea tag resolution is the trickiest logic. Example:
   - Template requiredIdeas: `["confirmation", "{quantity}", "{item}"]`
   - If `{quantity}` resolved to "deux", look up expression "deux" → ideaTags: `["quantity"]`
   - If `{item}` resolved to "café", look up expression "café" → ideaTags: `["item"]`
   - Final resolvedRequiredIdeas: `["confirmation", "quantity", "item"]`

2. **evaluate(selectedWords, requiredIdeas, bonusIdeas, hintLevel) → EvaluationResult**
   - Collect all ideaTags from selectedWords into a Set
   - Count how many requiredIdeas are covered
   - Count how many bonusIdeas are covered
   - Score:
     - PERFECT: all required covered AND at least 1 bonus covered
     - GOOD: all required covered
     - UNDERSTOOD: ≥50% of required covered
     - MISSED: <50% of required covered
   - Tip calculation: base tip (10) × score multiplier (PERFECT: 1.5, GOOD: 1.0, UNDERSTOOD: 0.5, MISSED: 0) × hint multiplier ([1.0, 0.75, 0.50][hintLevel])
   - Round tip to integer

3. **generateWordBank(resolvedExchange, playerVocabulary) → Expression[]**
   - Always exactly 8 tiles
   - Step 1: Include all expressions from playerVocabulary whose ideaTags intersect with requiredIdeas (these are the "answer" words)
   - Step 2: Fill remaining slots with distractors — other words from playerVocabulary that do NOT have any requiredIdea tags. Prefer words from the same stage.
   - Step 3: If still under 8, pad with any remaining vocabulary words
   - Step 4: Shuffle the array
   - SAFETY: assert that the bank contains at least one word for every required idea

4. **generateDay(templates, expressions, playerVocabulary, recencyBuffer) → ResolvedExchange[]**
   - Pick 8 templates. In M0: random selection. In M1: deprioritize (but don't exclude) templates in recencyBuffer (last 3 IDs).
   - For each template, call resolveTemplate.
   - Return array of 8 ResolvedExchange objects.
   - SAFETY: every exchange must be solvable. If resolveTemplate produces a bank that can't cover all required ideas, skip that template and pick another.

UI IMPLEMENTATION

**layout.tsx:**
- Set viewport meta tag for mobile
- Center a 390×844 container on the page
- Dark background (#1a1a2e or similar) outside the container
- The container has a warm background color

**page.tsx:**
- Single useState for game phase: 'dayStart' | 'gameplay' | 'summary'

**DayStartView:**
- Shows "Day {n}" prominently
- "Open Shop" button
- Warm cafe-themed background — this is the player's first impression. Should feel cozy.

**CafeScene.tsx (NEW — core visual component):**
This is the visual heart of the game. It makes the player feel like they're in a cafe, not a quiz app. Build it entirely with CSS and inline SVG — no external art assets.

- Layout: Takes up ~55% of the viewport height in the gameplay screen
- Background: Warm interior — wooden wall texture (CSS gradient), shelves with cups/jars (CSS shapes or simple inline SVG), a menu board, warm lighting feel
- Counter/bar: Horizontal surface at the bottom of the scene area where the customer stands. This is where the interaction happens visually.
- Atmosphere: Use CSS gradients, box-shadows, and subtle patterns to create warmth. Think warm browns, creams, soft lighting.
- This component is a visual backdrop — it doesn't handle game logic, just renders the scene.

**Customer.tsx (NEW — customer visual + speech bubble):**
- Customer silhouette/avatar: A simple CSS/SVG character shape positioned at the counter. Doesn't need to be detailed — a head + shoulders silhouette with a color accent is enough to sell "there's a person here."
- Speech bubble: Customer line text inside a styled speech bubble (with the pointed tail toward the customer). Replaces the plain text box.
- Patience bar: Positioned above the customer (not floating in empty space). Green bar that shrinks.
- Hint button: [?] button near the speech bubble area.
- Entrance transition: When a new customer arrives, slide in from the right (CSS translateX + opacity transition, ~0.4s).
- Exit transition: After scoring, customer slides out to the left (~0.3s), brief pause, next customer slides in.
- Score feedback: PERFECT/GOOD/etc text appears above the customer/counter area before the customer exits.

**GameplayView:**
- Top: HUD (coins, reputation, day number, customers remaining)
- Middle: CafeScene with Customer component layered on top (positioned at counter)
- Bottom: Response bar (shows selected words as removable chips) + word bank grid (tappable tiles) + Send button
- Word tiles: rounded rectangles with French text, ~48px tall, tap to add to response bar, tap in response bar to remove
- After Send: show score text and tip amount in the scene area for 1.5 seconds, then customer exits and next enters
- When all customers served, transition to summary

**SummaryView:**
- "Day {n} Complete!"
- Stats: customers served, perfect/good/understood/missed counts, coins earned, reputation change
- Words section: words practiced count, any level-ups (show "parce que → Level 2" etc)
- "Continue" button → saves state, advances to next day start

**Styling:**
- Use CSS modules or inline styles — no CSS framework
- Warm cafe color palette: cream/beige backgrounds, brown accents, warm gold for coins
- Cafe scene: wooden textures (CSS gradients), warm lighting (radial gradients), shelves and details (CSS shapes/inline SVG)
- Customer: simple silhouette with accent color, positioned at the counter
- Speech bubble: cream/white with subtle shadow, pointed tail toward customer
- Word tiles: solid colored rounded rectangles with white text
